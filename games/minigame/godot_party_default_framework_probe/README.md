# 框架测试小游戏

F5 启动正式工程，创建「原版协议 → 小游戏轮换」房间，在小游戏池里勾选「框架测试小游戏」并应用。只测试本包时仅勾选这一项。检查跨轮清理时，在大游戏配置中开启重复并将总局数设为 2。

1. 开局后，等所有端进入场景。房主点击「运行通信检查」，观察每端上行、定向可靠流和广播回执。单人时面板单列本机回环结果。参赛者可点「发送参赛操作」。
2. 房主可单独点击「检查父子通信」。正式轮换通过 PartyNet 回传自己锁定的请求编号，小游戏核对本次查询和请求编号。其他主游戏未实现该查询时，面板会显示超时。
3. 通信检查通过后，房主点击「结束并提交结果」。所有参赛者均以未排名或退出状态返回，轮换积分不变。父游戏负责正式提交和推进队列。
4. 同一会话下一次进入本包时，各端检查上一个实例的停止、关闭、退出、节点释放及旧 API 的发送返回值。首局没有上一局记录。

需要观战者时，在大厅选中本包，打开高级设置的「观战席位」，按大厅名单编号勾选。至少保留一位在线参赛者。选中房主席位后，房主仍能运行通信检查和提交结果，其「发送参赛操作」按钮禁用。默认所有在线玩家参赛。

本包只接受原版 standard 请求，独立于空白模板。源码即大厅可发现的小游戏，运行与扩展都在本目录进行。
