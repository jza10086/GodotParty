# GodotPartyDefault · 小游戏轮换

包 ID：`godot_party_default_maingame_minigame_playlist`。普通 maingame，沿用原版协议的 standard 排名局；1–8 人在线，具体人数取决于所选小游戏，使用正式大厅、加载屏障和持久化结算。

F5 → 创建房间 → 选择「GodotPartyDefault · 小游戏轮换」→ 大厅「小游戏池」→ 在卡片右上角勾选一个或多个兼容小游戏。支持 Ctrl 切换选择、Shift 连选与反选；右侧预设和高级设置只配置当前小游戏，未保存的高级设置作为一次性“临时预设”使用。总局数、轮换方式等从大厅独立的「大游戏配置」进入。所有玩家准备后开始。正常完成后自动进入下一局，全部完成后自动显示总成绩。

| 设置 | 默认 | 行为 |
| --- | --- | --- |
| 总局数 | 4 | 1–100；不允许重复时最多为所选游戏数量 |
| 轮换方式 | 顺序 | 顺序沿用大厅列表顺序，勾选先后不改变顺序；随机由房主生成队列 |
| 允许小游戏重复 | 开启 | 顺序循环列表；随机每局独立抽取，可能连续抽中同一项 |
| 局间间隔 | 0 秒 | 0–30；0 表示直接继续，不弹出阻断流程的单局成绩页 |

不允许重复时，顺序取列表前 N 项，随机洗牌后取前 N 项。队列在开始时生成并随大游戏状态保存；恢复存档不重新抽签。房间规则只在开局前调整。每轮默认选择所有仍在线的主游戏参与者，小游戏人数限制继续由框架检查。

测试单个原版小游戏：只勾选该项，开启允许重复，总局数设 1 为单次测试、设更大值为连续测试；无需修改小游戏入口或增加独立 runner。仍需满足小游戏的联机人数要求，不创建机器人或同屏玩家。

当前可选池开放霓虹回响（`gp_rhythm_game`，1–8 人，默认 Bad Apple!! 4K Normal）和阿瓦隆（`godot_party_default_identity_party`，5–8 人），并临时加入 `settings_ui_test`（设置 UI 测试）。在大厅“小游戏池”中单击测试卡片，再点右侧“本机设置”，即可测试 25 个示例项的 JSON 保存、协议继承和覆盖；无需勾选或开局。测试包是空白内容，没有回合结算玩法。其本机数据位于安装根目录 `minigame/settings_ui_test/config/`，与 tmp/test/ 下的 F6 预览资料独立。狼人杀和其他未完成小游戏仍不在可选池中。

每局已完成且有名次的玩家获得「本局参赛人数 − 名次 + 1」积分，并列同分；退出者不得该局积分。只有正式持久化的小游戏结果才能推进队列及加分。Tab 查看总积分，局间页可查看上一局成绩与完整队列。

加载失败、人数不足或小游戏取消时暂停轮换，不自动重试或计为已完成。房主可以重试相同队列位置，或提前结束并结算此前成绩；重试使用新的请求编号。保存失败由框架重试同一候选，避免重复发奖。房主退出结束会话；不实现运行中加入、重连或主机迁移。

本包负责房间界面、选择、连续启动和积分结算。`room.tscn` 复用现有公共房间场景，`room.gd` 驱动玩家列表、准备/开始、地址分享、配置入口和大厅语音；框架仍提供连接、设置/预设面板和持久化服务。主游戏不使用原版协议的金币、钻石或道具资源结算。

大厅默认只收听，麦克风关闭。点击“开启麦克风”前需在系统设置中明确授权并选择设备；“关闭收听”只影响本机接收。房主路由大厅全员语音，不回放自己的声音。修改房间规则会重建大厅作用域并关闭麦克风；开局、离开或断线时停止媒体并释放总线。返回大厅重新进入只收听状态。阿瓦隆和局间界面均不启用此大厅语音。

开发检查：通过正式大厅加载本包，勾选阿瓦隆并按需开启重复，使用编辑器五实例进行人工验收。定向检查与输出在 `tmp/test/playlist_room/`；旧测试归档仅作历史证据。合成 PCM 通路检查不等于真实麦克风、音质或外网验收。
