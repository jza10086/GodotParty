# GodotPartyDefault · 小游戏轮换

包 ID：`godot_party_default_maingame_minigame_playlist`。普通 maingame，沿用原版协议的 standard 排名局；1–8 人在线，具体人数取决于所选小游戏，使用正式大厅、加载屏障和持久化结算。

F5 → 创建房间 → 选择「GodotPartyDefault · 小游戏轮换」→ 大厅「小游戏池」→ 在左侧列表点击图标或名称查看右侧预览，用行末勾选框将游戏加入本房轮换。支持 Ctrl 切换选择、Shift 连选与反选；右侧预设和房间规则只配置当前小游戏，未保存的高级设置作为一次性“临时预设”使用。大厅下拉框切换顺序／随机轮换，「高级设置」调整轮换局数、避免游戏重复与局间间隔。所有玩家准备后开始。正常完成后自动进入下一局，全部完成后自动显示总成绩。

| 设置 | 默认 | 行为 |
| --- | --- | --- |
| 轮换局数 | 已选小游戏数 | 默认自动跟随选池；关闭自动后手动指定 1–100 局，配置中的 0 表示自动 |
| 轮换方式 | 顺序 | 顺序沿用大厅列表顺序，勾选先后不改变顺序；随机由房主生成队列 |
| 避免游戏重复 | 开启 | 仅随机模式显示并生效；开启后洗牌无放回，实际局数不超过已选数量；关闭后每局独立抽取 |
| 局间间隔 | 0 秒 | 0–30；0 表示直接继续，不弹出阻断流程的单局成绩页 |

大厅可直接勾选[空白小游戏](../../../minigame/gp_blank/doc/gp_blank_guide.md)，测试全员点击后的本轮排名。房主子实例发送 `playlist/round_query` 和整数 `nonce` 后，轮换控制器向当前子实例发送 `playlist/round_info`，载荷包含同一 `nonce` 和父游戏已锁定的 `request_id`。

顺序模式按列表循环至指定局数；随机且避免重复时，洗牌后取前 N 项，实际局数不超过选池数量。队列在开始时生成并随大游戏状态保存；恢复存档不重新抽签。房间规则只在开局前调整。每轮默认选择所有仍在线的主游戏参与者，小游戏人数限制继续由框架检查。

测试单个原版小游戏：只勾选该项，自动局数为 1；连续测试时关闭自动并指定更大局数，随机模式还需关闭避免游戏重复；无需修改小游戏入口或增加独立 runner。仍需满足小游戏的联机人数要求，不创建机器人或同屏玩家。

重启后，轮换会把 `games/minigame/<id>/manifest.json` 中声明兼容原版协议适配器的小游戏列为候选。房主勾选本房要玩的项目，开局人数取所选游戏支持人数的交集。

每局已完成且有名次的玩家获得「本局开始时锁定的参赛人数 − 小游戏给出的名次」积分，并列同分；退出者不得该局积分。只有正式持久化的小游戏结果才能推进队列及加分。主游戏发布累计积分与排名；按住 Tab 按总名次显示玩家、累计积分、到房主的往返延迟、连接状态和丢包率，并列保留主游戏顺序，未排名者置后。F3 仍可查看总积分，局间页可查看上一局成绩与完整队列。

加载失败、人数不足或小游戏取消时暂停轮换，不自动重试或计为已完成。房主可以重试相同队列位置，或提前结束并结算此前成绩；重试使用新的请求编号。保存失败由框架重试同一候选，避免重复发奖。房主退出结束会话；不实现运行中加入、重连或主机迁移。

本包负责房间界面、选择、连续启动和积分结算。`room.tscn` 复用现有公共房间场景，`room.gd` 驱动玩家列表、准备/开始、地址分享、配置入口和大厅语音；框架仍提供连接、设置/预设面板和持久化服务。主游戏不使用原版协议的金币、钻石或道具资源结算。

大厅默认只收听，麦克风关闭。点击“开启麦克风”前需在系统设置中明确授权并选择设备；“关闭收听”只影响本机接收。房主路由大厅全员语音，不回放自己的声音。修改房间规则会重建大厅作用域并关闭麦克风；开局、离开或断线时停止媒体并释放总线。返回大厅重新进入只收听状态。阿瓦隆和局间界面均不启用此大厅语音。

开发检查：通过正式大厅加载本包，勾选阿瓦隆并按需配置局数与随机去重，使用编辑器五实例进行人工验收。定向检查与输出在 `tmp/test/playlist_room/`；旧测试归档仅作历史证据。合成 PCM 通路检查不等于真实麦克风、音质或外网验收。

炮火争锋已接入正式对局：自由混战 2–8 人、团队对抗 2/4/6/8 人、单人测试 1 人；在房间规则中选择模式。
