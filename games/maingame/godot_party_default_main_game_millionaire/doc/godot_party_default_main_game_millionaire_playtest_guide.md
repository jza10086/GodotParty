# 独立棋盘流程测试

在 Godot 打开 board_playtest.tscn，按 F6。此场景使用独立 Cell 地图，不加载或写入尚未完成的 map_preview.tscn，不是正式联机游戏或另一个框架启动器。

右下角掷骰，原版形象包的 Cube 棋子逐格移动，蓝色材质代表玩家颜色；分叉弹窗选择出口。中键旋转、Shift+中键平移、滚轮缩放，R 重置视角，N 显示地格 ID。测试仅有一名操作玩家，没有同屏多人或 AI。棋盘负责位置与结算；pawn_scene 可在检查器替换为支持 apply_color(Color) 的 Node3D 场景，不要求动画接口。

## 已接通
- 复用 GodotPartyUI 的 monopoly_overlay / monopoly_game，包括钱包、排行、背包和不可关闭的交互弹窗。导入至 core/ui/source，仅重定向资源路径，复用现有主题依赖。
- KayKit D6_A 白色六面骰，原尺寸 0.75 米；独立刚体骰盘，不与棋盘、人物交互。
- 控制器先抽取 1–6，表现层接受点数和独立视觉 seed，物理翻滚 1.8 秒后用 0.65 秒受控动画收尾，停留 0.35 秒后开始移动。超时或出界采用同一收尾，不重抽结果。不是纯物理随机。
- 模型面向由原资产点窝几何核对：-Y=1、+X=2、+Z=3、-Z=4、-X=5、+Y=6。
- 起点单向进入道路；分叉不扣步，其他地格进入扣步。商店、钻石经过交互；地产、事件最终停留结算。
- 按钮与控制器双层阶段检查；事件 ID、可选操作和阶段检查防止重复扣款。相机/渲染复用原版协议画质桥接。

## 测试规则，不代表正式经济
初始 1000 金币；测试道具 100，钻石 200，地产购置 150、升级 100。随机事件只提示；道具效果、租金、加价收购、结束排名与联机暂未实现。正式接入时由房主决定点数并同步逻辑结果，各端骰子只是表现；当前 F6 不发送网络消息。
