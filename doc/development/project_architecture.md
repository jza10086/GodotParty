# 项目架构与开发边界

执行规则见根目录 [AGENTS.md](../../AGENTS.md)，具体接口从 [公共契约索引](../project_index.md#公共契约) 进入。

| 目录或模块 | 职责 |
| --- | --- |
| `core/` | 正式主菜单、大厅连接、会话协调、加载、状态提交、注入式 PartyAPI、公共 UI 和安装挂载 |
| `games/protocols/<id>/` | 业务协议、玩家资料、公共偏好和可选准备/结算展示；形象包位于所属协议 `avatars/` |
| `games/maingame/<id>/` | 大游戏持久状态、房间界面、游戏池、玩法编排与纯结果归约；轮换也是大游戏 |
| `games/minigame/<id>/` | 一局玩法状态、表现、输入与计算；中游戏仅以 tag 标注 |
| `games/assets/<id>/` | 独立叶子资产包，引用自身或公开 core 资源，不依赖其他内容包 |
| `doc/` | 项目规范、公开契约与跨包索引 |

## 运行边界

完整工程和正式主菜单/大厅是开发入口，启动参数只选择正式流程输入。宿主持有唯一连接和协调器；PartyAPI 按作用域注入，不作为 Autoload。启动目录扫描只读清单和轻量定义，实际使用时才加载运行资源。

一个顶层主游戏只启动一个前台子活动；未参赛者观战，观战房主仍运行协调及必要的房主逻辑。主游戏控制器与长期状态跨子活动保留，视图在前台切换时释放和重建；普通状态提交更新现有视图。经济、奖励、回合和胜负语义由主游戏及协议拥有。

小游戏使用普通节点的 `party_setup`、`party_start`、`party_stop`，初始化后显式 `mark_ready`。房主拥有最终发布权，作者根据玩法选择本地、房主或混合计算。长期状态可序列化，结果归约为纯函数，提交完成后才公布奖励。参见 [生命周期](../api/activity_lifecycle.md) 与 [状态和结算](../api/main_game_state.md)。

## 内容与版本

`manifest.json` 是作者维护的内容清单，`definition.gd` 提供不依赖玩法场景的目录信息。框架版本、内容版本、依赖匹配与随机构建标识统一见 [内容包声明](../api/content_packages.md#声明版本与包身份)。不使用文件哈希校验；Godot 项目版本由用户维护。

同进程内容具有普通 Godot 脚本能力；保留版本、依赖、路径和资源冲突校验，不提供内容沙箱。仅维护当前接口和数据格式，不新增旧格式迁移层。资源制作、署名与排除边界见 [外部资源](../api/external_resources.md)。
