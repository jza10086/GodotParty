## 定向验证

遵循用户级 `~/.codex/AGENTS.md` 的通用测试规范。先明确当前变更需要回答的问题，再选最小验证：文档与注释只做文本检查，简单配置只检查语法和值，局部逻辑优先复用相关现有测试。仅为重要行为、复杂规则或已知回归新增测试，不为低风险小改动建立测试框架或大型模拟环境。

涉及网络资料、配置生效或持久化时，只验证本次受影响的成功与失败路径；仅在验证依赖实际通信时运行主客机检查。只有具体的共享依赖变化、跨模块影响或异常证据才扩大到集成或全项目检查，模块完成或提交本身不触发额外测试。同一问题选一种合适的检查方式，相关检查通过后停止，不用重建旧的整套测试，也不进行文件哈希校验。

所有画面测试只使用 **1920x1080**，包括验收预览、截图、人工视觉检查和自动布局检查，不增加其他分辨率、超宽屏或多分辨率矩阵。视觉调整优先使用现有预览和人工检查，只有明确的布局数值需求才添加数值断言。

Godot CLI 验证前确认 godot --version。临时脚本可通过 --headless --path . --script res://tmp/test/<功能>/<脚本>.gd 运行，日志用 --log-file 指向同一测试目录。使用退出码和 ERROR / SCRIPT ERROR 判定结果；故意触发的负向用例必须与意外错误明确区分。

## 人工多人验收

使用编辑器多实例功能和正式主菜单/大厅，每个实例指定不同的 --party-profile=<slot>。这些开发资料位于 tmp/test/profiles/<slot>/，与原玩家资料隔离；旧 tmp/profiles/ 不自动迁移。

按本次变更范围人工确认受影响的建房、直连、资料同步、准备、活动切换或断开流程，不默认逐项验收。界面、输入、手感、音频设备与多人体验需要人工操作；画面检查统一为 1920x1080。本机 ENet 检查不能证明外网 IPv6、NAT、防火墙或 Steam 可用。交付时如实区分静态检查、自动化测试、运行验证和人工验收。
